It remains an alternate concept in source; the existing root homepage is older. Treat Design 09 as the intended candidate when preparing the migration preview.
- Design 09 currently has `noindex`, old-domain canonical/social URLs, archive navigation, and the summer 2027 **interest-list** workflow. Moving it to the homepage must address these intentionally without silently changing it to active appointment booking.
- The build uses **vinext** and a custom static exporter. `scripts/export-github-pages.mjs` assumes a repository-prefixed path; `scripts/export-manifest.json` freezes existing HTML/source. Moving the same artifact unchanged to a domain root will not reliably fix links or metadata. Preserve the approved design and deliberately update export behavior.
- `cloudflare/consultation/README.md` and Wrangler configuration describe an existing separate consultation Worker, a Tyche-domain sender, the owner's current Gmail destination, exact old-origin restrictions and Turnstile. These are configuration and historical-delivery findings; live delivery was not retested in this planning review.
- The research library and root `AGENTS.md` are currently untracked local files. A remote repository transfer alone will not include them. Review and preserve authorized local work before migration; do not blindly publish every untracked business document, temporary file or cache.

## Decisions that prevent rework

**Hosting.** Cloudflare now recommends Workers for new projects. GitHub Pages has restrictions on hosting online businesses and primarily commercial-transaction sites; use GitHub for source rather than committing this business to new GitHub Pages hosting. This is a prospective architecture recommendation, not a finding that the existing brochure violates its terms. Keep the public site static where practical; script execution, builds and mail have separate limits/costs from static requests. [Cloudflare direction](https://developers.cloudflare.com/pages/), [static-asset billing](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/), [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).

**Transfer and redirects.** GitHub preserves repository history and associated resources on transfer, but does not redirect the corresponding Pages site. Do not create a competing target repository that blocks transfer or recreate the old repository address and erase GitHub's repository redirect. Coordinate the move with hosting and separately controlled old-site redirects. Google's migration guidance recommends retaining redirects generally at least one year. Only the electrology subpath is moving: do not submit a whole-domain Change of Address for Tyche or redirect unrelated content. [GitHub transfer](https://docs.github.com/en/repositories/creating-and-managing-repositories/transferring-a-repository), [Google migration](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes), [Change of Address scope](https://support.google.com/webmasters/answer/9370220).

**Email.** Reserve the Evergreen root MX records for Zoho. Cloudflare Email Routing and Zoho should not both be configured as competing inbound providers for the same domain. Cloudflare's newer Email Sending uses a separate bounce subdomain; evaluate availability, authentication and pricing when selecting outbound sending. Do not enable temporary root Email Routing on Evergreen solely to send a form notification. The existing recipient variable and binding destination must remain aligned. [Cloudflare domain setup](https://developers.cloudflare.com/email-service/configuration/domains/), [binding restrictions](https://developers.cloudflare.com/email-service/configuration/send-bindings/), [Zoho delivery setup](https://www.zoho.com/mail/help/adminconsole/configure-email-delivery.html).

**Preview/toolchain.** Current isolated Workers Previews require Wrangler 4.135.0 or later; this repo declares 4.92.0. Test an intentional upgrade or use a separate staging deployment. Do not assume older public Version URLs isolate production resources. Rollback also does not restore external services/data; preserve the relevant configuration and artifact. [Workers Previews](https://developers.cloudflare.com/workers/previews/), [Version URLs](https://developers.cloudflare.com/workers/versions-and-deployments/version-urls/), [rollback](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/).

**Scope.** The organization handle, source visibility, precise account permissions, final publishing decision, production mailbox name, DNS records and complete legacy deployment inventory remain to be established. This plan supplies an order that permits those facts to be checked before consequential changes. Recheck relevant platform documentation at implementation time.
