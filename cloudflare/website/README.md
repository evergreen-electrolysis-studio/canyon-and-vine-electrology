# Evergreen website migration preview

This is the separate, static website artifact for the planned migration to
`evergreenelectrolysisstudio.com`. It does not change the existing GitHub Pages
or Sites deployments or the consultation Worker.

Verified staging preview:
https://evergreen-website-preview.sukhpalc.workers.dev/ .
This preview is excluded from indexing and cannot send inquiries to the inbox.
Its deployed version and checks are recorded in
`docs/electrology/MIGRATION_STATUS.md`.

## Source and build

`app/evergreen/page.tsx` is the new authoring route. It starts from the approved
Design 09 and reuses its unchanged CSS, images, rates and form components. The
exporter renders that route as the **public homepage `/`**, not `/evergreen/`.
Historical source and published snapshots stay protected by the existing
export manifest.

```sh
pnpm run build:evergreen
pnpm run preview:evergreen
```

The preview exports to ignored `out/evergreen/`. It is excluded from indexing
using page metadata and HTTP headers. Its form uses a public Turnstile test key
and a same-origin `/__preview__/request` endpoint that has no delivery backend.
Use fictional inputs; a preview submission must not claim a real signup or send
email. The unchanged production form controller can be tested for validation
and failure recovery against this artifact.

Run `pnpm test` for the historical checks, frozen hashes, form/Worker regressions
and new export checks. The website preview should also be checked in a browser
at desktop/mobile widths and through the local static-assets runtime; verify a
missing URL returns a real HTTP 404.

## Production preparation

After verifying the actual domain, indexing readiness, form-origin and Turnstile
configuration, the exporter supports an explicit production artifact:

```sh
node scripts/export-evergreen.mjs --production
```

Production output is separate in `out/evergreen-production/`. The preview
Wrangler configuration does **not** deploy that directory. Before a production
cutover, add the verified account and canonical custom-domain deployment
configuration, establish the old-URL redirects and rollback path, and verify
real form-to-inbox delivery. The current CLI/connector identity and repository
ownership are recorded in `docs/electrology/MIGRATION_STATUS.md`.

Do not point Cloudflare at the whole repository, `dist/`, or `github-pages/`.
Publish only the new static artifact. Its real 404, sitemap, robots directives
and root-relative assets are generated by `scripts/export-evergreen.mjs`.
No health-history or consent records belong in this public artifact.

The approved preview retains the existing licensure statement and studio
facts. Their source approval is not independent license verification. Resolve
the remaining factual checks in the project research before the live cutover.

## Routing and rollback

Cloudflare's static assets support `404-page` and `auto-trailing-slash` routing.
The `_headers` file supplies preview indexing and response-header directives.
See [static-site routing](https://developers.cloudflare.com/workers/static-assets/routing/static-site-generation/)
and [headers](https://developers.cloudflare.com/workers/static-assets/headers/)
(reviewed November 17, 2026).

Configure hostname redirects (`www` to apex) and legacy Tyche-path redirects at
the serving zone/Worker. The new site's `_redirects` file cannot redirect a
request that still reaches GitHub or match arbitrary source domains. Preserve
old relevant URLs with permanent redirects after verification, and leave
unrelated Tyche content alone.

The verified original history and research snapshot are in the local
`.git/migration-backups/evergreen-start-074c9b2/` directory. Keep the original
deployments available until the replacement and redirects are tested. Do not
push preliminary work to `main`: its existing workflow publishes GitHub Pages.
